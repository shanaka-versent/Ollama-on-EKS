CRIT 1. Containers Run as Root (No SecurityContext)

k8s/ollama/deployment.yaml, k8s/open-webui/deployment.yaml, k8s/model-loader/job.yaml

Risk: All containers run as UID 0. Container escape = full node compromise. Fails CIS Kubernetes Benchmark 5.2.6.

How to Fix

Add securityContext to each container spec. Ollama needs write access to /root/.ollama, so use a non-root UID with matching volume permissions:

# k8s/ollama/deployment.yaml — add under containers[0]
securityContext:
  runAsNonRoot: true
  runAsUser: 1000
  runAsGroup: 1000
  allowPrivilegeEscalation: false
  seccompProfile:
    type: RuntimeDefault
  capabilities:
    drop: ["ALL"]

# Also add initContainer to fix volume permissions:
initContainers:
  - name: fix-permissions
    image: busybox:1.36
    command: ["sh", "-c", "chown -R 1000:1000 /root/.ollama"]
    volumeMounts:
      - name: ollama-models
        mountPath: /root/.ollama

Repeat for open-webui (UID 1000, mount /app/backend/data) and model-loader job.

Test: kubectl exec -n ollama deploy/ollama -- id → should show uid=1000

CRIT 3. No PodDisruptionBudgets

Missing resource — all namespaces

Risk: Cluster upgrades, node drains, and Karpenter consolidation terminate all replicas simultaneously. Guaranteed outage during any maintenance.

How to Fix

# k8s/ollama/pdb.yaml
apiVersion: policy/v1
kind: PodDisruptionBudget
metadata:
  name: ollama
  namespace: ollama
spec:
  maxUnavailable: 0        # Never evict voluntarily when running
  selector:
    matchLabels:
      app: ollama
---
# k8s/open-webui/pdb.yaml
apiVersion: policy/v1
kind: PodDisruptionBudget
metadata:
  name: open-webui
  namespace: open-webui
spec:
  maxUnavailable: 0
  selector:
    matchLabels:
      app: open-webui

Add these files to the respective ArgoCD app paths. For Ollama (single replica + GPU), maxUnavailable: 0 prevents Karpenter from draining mid-inference. Cluster upgrades will wait for the pod to finish.

Test: kubectl drain <node> --ignore-daemonsets — should block with "Cannot evict pod (PDB)".

CRIT 4. Missing Startup Probe on Ollama

k8s/ollama/deployment.yaml:73-86

Risk: Model loading takes 2-4 minutes. Liveness probe fires at ~70s, marking pod unhealthy. Kubelet kills and restarts it — infinite restart loop on every cold start.

How to Fix

# k8s/ollama/deployment.yaml — add BEFORE livenessProbe
startupProbe:
  httpGet:
    path: /api/tags
    port: 11434
  initialDelaySeconds: 30
  periodSeconds: 15
  failureThreshold: 20    # 30 + (15 x 20) = 330s = 5.5 min grace
  # Liveness/readiness probes are suppressed until startupProbe passes

The startup probe gives Ollama up to 5.5 minutes to load the model before liveness kicks in. Once startup succeeds, the normal liveness/readiness probes take over.

Test: Scale Ollama from 0 → 1. Watch: kubectl get pods -n ollama -w. Pod should stay in Running (not CrashLoopBackOff) during model load.

CRIT 5. Single AZ System Nodes

k8s/nodepools/system-nodepool.yaml

Risk: All system pods (CoreDNS, Istio, ArgoCD, Prometheus, Open WebUI) in ap-southeast-2a. AZ failure = complete platform outage, 30+ min RTO.

How to Fix

# k8s/nodepools/system-nodepool.yaml — change zone constraint
spec:
  template:
    spec:
      requirements:
        - key: topology.kubernetes.io/zone
          operator: In
          values:
            - ap-southeast-2a
            - ap-southeast-2b     # ADD THIS

      # Also add: spread pods across AZs
      topologySpreadConstraints:
        - maxSkew: 1
          topologyKey: topology.kubernetes.io/zone
          whenUnsatisfiable: DoNotSchedule

Then add topologySpreadConstraints to Open WebUI deployment (when running 2+ replicas) to spread across AZs.

Cost: +$60/mo (second t3.xlarge in 2b). Benefit: 99.99% system availability.

Note: Open WebUI PVC (EBS) is AZ-bound. Either: (a) use EFS instead of EBS for cross-AZ access, or (b) keep Open WebUI pinned to 2a and accept that UI fails during 2a outage while API (GPU in 2b) stays up.

CRIT 6. No Open WebUI Data Backup

Missing resource — no DLM policy for open-webui PVC

Risk: Chat history + user preferences stored in SQLite on EBS PVC. EBS failure = total data loss. No snapshots, no backup schedule.

How to Fix

# terraform/main.tf — add Data Lifecycle Manager policy
resource "aws_dlm_lifecycle_policy" "webui_backup" {
  description        = "Daily backup of Open WebUI data volume"
  execution_role_arn = aws_iam_role.dlm.arn
  state              = "ENABLED"

  policy_details {
    resource_types = ["VOLUME"]
    target_tags    = { Name = "open-webui-data" }

    schedule {
      name = "daily-2am"
      create_rule { interval = 24; interval_unit = "HOURS"; times = ["02:00"] }
      retain_rule { count = 7 }  # Keep 7 daily snapshots
      tags_to_add  = { SnapshotType = "DLM-automated" }
    }
  }
}

# IAM role for DLM
resource "aws_iam_role" "dlm" {
  name               = "${var.project_name}-dlm"
  assume_role_policy = jsonencode({
    Version = "2012-10-17"
    Statement = [{
      Action = "sts:AssumeRole"
      Effect = "Allow"
      Principal = { Service = "dlm.amazonaws.com" }
    }]
  })
}

resource "aws_iam_role_policy_attachment" "dlm" {
  role       = aws_iam_role.dlm.name
  policy_arn = "arn:aws:iam::aws:policy/service-role/AWSDataLifecycleManagerServiceRole"
}

Tag the Open WebUI EBS volume with Name = open-webui-data so DLM can find it.

Cost: ~$5/mo (7 daily snapshots of ~10GB volume). Recovery: Restore any snapshot to a new volume in <5 min.

CRIT 8. Scripts Missing Trap Handlers — KEDA Left Paused

scripts/scale-up.sh, switch-model.sh

Risk: If Ctrl+C is pressed while KEDA is paused (during model loading), KEDA stays paused indefinitely. GPU node runs 24/7 at $0.35-$1.90/hr until someone notices.

How to Fix

# Add at the TOP of scripts/scale-up.sh and switch-model.sh (after set -e)

cleanup() {
  echo ""
  log "Interrupted! Ensuring KEDA is unpaused..."
  kubectl annotate scaledobject ollama-autoscaler -n ollama \
    autoscaling.keda.sh/paused- \
    gpu-controller/paused-at- \
    --overwrite 2>/dev/null || true
  warn "KEDA unpaused. Check GPU node status: kubectl get nodes"
  exit 1
}

trap cleanup INT TERM EXIT

# ... rest of script ...

# At the END of the script (on success), remove the trap:
trap - INT TERM EXIT

This ensures KEDA is always unpaused, even on Ctrl+C, terminal close, or script error. The trap - EXIT at the end prevents cleanup from running on normal exit (since the script itself unpauses KEDA in the success path).

Test: Run ./scripts/scale-up.sh, press Ctrl+C during model load. Verify: kubectl get scaledobject -n ollama — PAUSED should be false.

HIGH 5. Single NAT Gateway (SPOF for Egress)

terraform/modules/vpc/main.tf:73-84

Risk: All private subnet egress routes through one NAT in ap-southeast-2a. NAT failure = no outbound connectivity.

How to Fix

# Option A: NAT per AZ (high availability, +$32/mo)
resource "aws_nat_gateway" "main" {
  count         = var.enable_nat_gateway ? length(var.azs) : 0
  allocation_id = aws_eip.nat[count.index].id
  subnet_id     = aws_subnet.public[count.index].id
}

# Option B: VPC endpoints to eliminate NAT for most traffic (cheaper)
# Add endpoints for: ECR, S3, DynamoDB, CloudWatch, STS
resource "aws_vpc_endpoint" "ecr_api" {
  vpc_id            = aws_vpc.main.id
  service_name      = "com.amazonaws.${var.region}.ecr.api"
  vpc_endpoint_type = "Interface"
  subnet_ids        = aws_subnet.private[*].id
}

Option B is more cost-effective: VPC endpoints are cheaper than NAT Gateway and eliminate egress traffic charges for AWS services.

import boto3, json

def handler(event, context):
    k8s = boto3.client('eks')
    # Check if Ollama is at 0 replicas (via CloudWatch metric or K8s API)
    # If 0: trigger scale-up, return 503
    # If running: proxy request to NLB
    return {

ARCH 2. Open WebUI: Recreate → RollingUpdate

Current: strategy: Recreate causes downtime on every deployment.

# k8s/open-webui/deployment.yaml
strategy:
  type: RollingUpdate
  rollingUpdate:
    maxSurge: 1
    maxUnavailable: 0

Note: Open WebUI uses SQLite on a PVC. With RollingUpdate, two pods briefly share the PVC. SQLite handles concurrent reads but not concurrent writes. Since only one pod processes OAuth callbacks at a time (via cookie affinity), this is safe.

ARCH 3. HPA for Open WebUI (Auto-Scale on Load)

Current: Fixed 1 replica. Under concurrent user load, response times degrade.

ARCH 9. Istio Waypoint Proxy for L7 Per-User Rate Limiting
