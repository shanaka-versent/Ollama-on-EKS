Executive Summary

The platform is well-architected for a dev/consulting engagement. The CloudFront + VPC Origins pattern replaced Kong (99% cost reduction), KEDA + Karpenter deliver true scale-to-zero ($0/hr idle GPU), and EBS snapshots enable 3-minute cold starts. However, 8 critical findings should be addressed before production use, primarily around container security, IAM over-permission, and single-AZ resilience.

Strengths

  • CloudFront + WAF replaces Kong Gateway: $756/mo → $6/mo (99% reduction)
  • KEDA auto-scale-to-zero + Karpenter node termination = $0/hr idle GPU cost
  • EBS snapshots: 3-min cold start vs 15-25 min internet pull (air-gap compliant)
  • Flex-mode tier switching via switch-model.sh — no manifest edits needed
  • Custom Cognito portal — users never see hosted UI, mandatory TOTP MFA
  • All traffic stays on AWS backbone (VPC Origins, no internet-facing LB)

Critical Findings (Fix Before Production)

CRITICAL   1. Containers Run as Root

Files: k8s/ollama/deployment.yaml, k8s/open-webui/deployment.yaml, k8s/model-loader/job.yaml

No securityContext defined — all containers run as UID 0 (root) with full privilege escalation.

# Fix: Add to each container spec
securityContext:
  runAsNonRoot: true
  allowPrivilegeEscalation: false
  capabilities:
    drop: ["ALL"]

CRITICAL   2. GitHub Actions IAM Role: PowerUserAccess

File: terraform/modules/iam/main.tf:189

GitHub Actions assumes a role with PowerUserAccess — compromised workflow = full AWS account access except IAM.

# Fix: Replace with scoped policy
policy_arn = aws_iam_policy.github_actions_terraform.arn  # Custom, least-privilege

CRITICAL   3. No PodDisruptionBudgets

Files: All deployments

No PDBs defined. Cluster upgrades, node drains, and Karpenter consolidation can terminate all replicas simultaneously — guaranteed outage during maintenance.

CRITICAL   4. Missing Startup Probe on Ollama

File: k8s/ollama/deployment.yaml:73-86

Model loading takes 2-4 minutes, but liveness probe kicks in at ~70s. Pod enters restart loop on every cold start.

# Fix: Add startup probe with generous timeout
startupProbe:
  httpGet:
    path: /api/tags
    port: 11434
  initialDelaySeconds: 60
  periodSeconds: 30
  failureThreshold: 8   # 300s total grace period

CRITICAL   5. Single AZ System Nodes

File: k8s/nodepools/system-nodepool.yaml

All system pods (CoreDNS, Istio, ArgoCD, Prometheus, Open WebUI) run on a single node in ap-southeast-2a. AZ failure = complete platform outage, 30+ min RTO.

CRITICAL   6. No Open WebUI Data Backup

Open WebUI stores chat history + user data in SQLite on an EBS PVC. No automated backup, no snapshot schedule. PVC failure = total data loss.

CRITICAL   7. EKS Control Plane Logging Disabled

File: terraform/variables.tf:61 — enable_logging = false

No CloudWatch audit trail for API calls, auth events, or controller actions. Cannot investigate security incidents.

CRITICAL   8. Script Trap Handlers Missing — KEDA Left Paused

Files: scripts/scale-up.sh, switch-model.sh

If interrupted (Ctrl+C) while KEDA is paused, it stays paused indefinitely. GPU node runs forever at $0.35-$1.90/hr.

# Fix: Add trap handler at script start
trap 'kubectl annotate scaledobject ollama-autoscaler -n ollama \
  autoscaling.keda.sh/paused- --overwrite 2>/dev/null; exit 1' INT TERM

deploy-stack-a.sh doesn't verify S3 backend, DynamoDB lock table, or service quotas before starting Terraform.

MED Silent failures in scripts

All scripts use [INFO] prefix without timestamps. Hard to correlate events during incident response.

Architecture Improvements

Current Architecture Gaps

HIGH   Auto Scale-from-Zero for First Request

Current: KEDA scales to zero after 15 min idle, but scaling back UP requires manual ./scripts/scale-up.sh.

Improvement: Add a lightweight API Gateway Lambda that detects the first inference request when Ollama is at 0 replicas, automatically triggers scale-up, and returns a "warming up" response. Subsequent requests route normally once the pod is ready.

# API Gateway → Lambda (check replicas) → if 0: trigger scale-up + return 503 Retry-After
# CloudFront custom error page shows "Model loading, please wait ~3 min"

Benefit: Fully automatic cold start — no SSH/kubectl needed. Users just wait ~3 min on first request.

HIGH   Open WebUI: Switch from Recreate to RollingUpdate

Current: strategy: Recreate — every deployment causes downtime while old pod terminates and new one starts.

Improvement: Switch to RollingUpdate with maxSurge: 1, maxUnavailable: 0. Open WebUI is stateless enough (SQLite on shared PVC) — new pod starts, gets healthy, then old pod terminates. Zero downtime.

Benefit: Users never see downtime during Open WebUI config changes or version upgrades.

MED   Horizontal Pod Autoscaler for Open WebUI

Current: Fixed 1 replica. Under concurrent user load, response times degrade.

Improvement: Add HPA scaling Open WebUI from 1→3 replicas based on CPU (70% target). Karpenter handles additional system node if needed.

apiVersion: autoscaling/v2
kind: HorizontalPodAutoscaler
spec:
  scaleTargetRef: {kind: Deployment, name: open-webui}
  minReplicas: 1
  maxReplicas: 3
  metrics:
    - type: Resource
      resource: {name: cpu, target: {type: Utilization, averageUtilization: 70}}

Benefit: Auto-scales for concurrent users without over-provisioning at idle.

MED   Move Hardcoded Env Vars to ConfigMaps

Current: 30+ env vars hardcoded in deployment YAML. Changing OLLAMA_NUM_PARALLEL or AIOHTTP_CLIENT_TIMEOUT requires a manifest edit + ArgoCD sync + pod restart.

Improvement: Move tunable parameters to a ConfigMap. ArgoCD detects ConfigMap changes and triggers rolling restart automatically.

Benefit: Runtime tuning without touching deployment manifests. Faster iteration during load testing.

MED   Vertical Pod Autoscaler (VPA) in Recommendation Mode

Current: Resource requests/limits set manually. Ollama requests 1 CPU but actual usage varies by model tier.

Improvement: Install VPA in recommendation-only mode. Review quarterly and adjust requests to match actual usage. Prevents over-provisioning (Karpenter picks smaller/cheaper instances when requests are lower).

Benefit: Right-sized pods → Karpenter picks optimal instance types → lower cost.

MED   Implement Velero for Full Cluster Backup

Current: No backup strategy for K8s resources or PVCs. If ArgoCD state or Open WebUI data is lost, manual reconstruction required.

Improvement: Deploy Velero with S3 backend. Schedule daily backups of all namespaces + PVCs. Enables full disaster recovery and cluster migration.

helm install velero vmware-tanzu/velero --namespace velero \
  --set configuration.backupStorageLocation.bucket=ollama-velero-backups \
  --set schedules.daily.schedule="0 2 * * *"

Benefit: Full cluster recovery in <30 min. Enables environment cloning for staging.

LOW   Canary Deployments for Model Updates

Current: Model switches are all-or-nothing via switch-model.sh. If a new model has quality issues, all users are affected.

Improvement: Use Istio traffic splitting + Flagger to route 10% of traffic to the new model tier, validate quality metrics, then gradually shift to 100%.

Benefit: Safe model rollouts with automatic rollback on quality regression. Relevant when moving to production with paying clients.

LOW   GitOps for Secret Management (ESO + AWS Secrets Manager)

Current: Terraform creates K8s secrets directly. No rotation, no audit trail, secrets in Terraform state.

Improvement: External Secrets Operator syncs secrets from AWS Secrets Manager → K8s. Secrets Manager handles rotation. Terraform only manages the SM secret, not the K8s resource.

Benefit: Automatic secret rotation. Audit trail via CloudTrail. Secrets never in Terraform state.

LOW   Istio Waypoint Proxy for L7 Policy (Future)

Current: Istio ambient mesh provides L4 mTLS via ztunnel. No L7 policies (rate limiting, retries, circuit breaking) per service.

Improvement: Add Istio waypoint proxy for the Ollama namespace to enable per-user rate limiting, retry policies, and circuit breaking at L7. This complements the WAF rate limit (which is per-IP, not per-user).

Benefit: Fine-grained traffic management. Prevents single user from monopolizing GPU.
