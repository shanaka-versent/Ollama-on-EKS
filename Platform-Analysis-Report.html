Missing resource — all namespaces

PDB with maxUnavailable: 0 on single-replica deployments blocks drain forever — creates a different problem

Why This Is Deferred

PDB with maxUnavailable: 0 on single-replica deployments conflicts with 2 existing mechanisms:

ComponentConflict?Detail
KEDA scale-to-zeroNoKEDA changes replica count (scaling), not eviction. PDB doesn't apply.
switch-model.shNoPatches deployment spec → triggers rollout. Rollouts are not evictions.
ArgoCD selfHeal/syncNoUpdates deployment spec → rollout. Not an eviction.
Spot instance reclaimNoAWS force-terminates the instance. PDB only applies to voluntary evictions.
Karpenter GPU consolidationNoUses WhenEmpty — only fires when Ollama is already at 0 replicas (no pods to evict).
Karpenter system node consolidationYESSystem NodePool uses WhenEmptyOrUnderutilized. Karpenter wants to move pods to a smaller node, but PDB blocks eviction of the single replica forever. Node can never be consolidated.
EKS node upgrades (kubectl drain)YESkubectl drain tries to evict pods. With 1 replica + maxUnavailable: 0, drain hangs forever. Node upgrade stalls.

Decision: Accepted Risk

Status: Deferred — Brief outages during maintenance are acceptable for the current dev/consulting phase. Cluster updates are infrequent (monthly at most). The team accepts 2-3 minutes of downtime during planned node drains.

Revisit when: Moving to production with SLA requirements, or when Open WebUI runs 2+ replicas via HPA (at which point maxUnavailable: 1 works correctly with multi-replica).

What Would Work (Future)

  • Ollama: Skip PDB entirely. GPU workload tolerates spot interruptions (2-3 min). KEDA + Karpenter manage its lifecycle.
  • Open WebUI with HPA (2+ replicas): PDB maxUnavailable: 1 allows drains while keeping at least 1 replica running.
# Only implement after HPA is enabled (Architecture item #3):
# k8s/open-webui/pdb.yaml
apiVersion: policy/v1
kind: PodDisruptionBudget
metadata:
  name: open-webui
  namespace: open-webui
spec:
  maxUnavailable: 1       # Allow drain (evict 1 at a time)
  selector:               # But HPA keeps minReplicas: 2
    matchLabels:           # so 1 replica always serves traffic
      app: open-webui

# terraform/main.tf — add Data Lifecycle Manager policy
resource "aws_dlm_lifecycle_policy" "webui_backup" {
  description        = "Daily backup of Open WebUI data volume"
  execution_role_arn = aws_iam_role.dlm.arn
  state              = "ENABLED"

  policy_details {
    resource_types = ["VOLUME"]
    target_tags    = { Name = "open-webui-data" }

    schedule {
      name = "daily-2am"
      create_rule { interval = 24; interval_unit = "HOURS"; times = ["02:00"] }
      retain_rule { count = 7 }  # Keep 7 daily snapshots
      tags_to_add  = { SnapshotType = "DLM-automated" }
    }
  }
}

resource "aws_iam_role" "dlm" {

CRIT 8. KEDA GPU Auto-Shutdown Protection — FIXED

scripts/scale-up.sh, switch-model.sh

Original risk: If Ctrl+C was pressed while KEDA was paused (during model loading), KEDA stayed paused indefinitely. GPU node would run 24/7 at $0.35-$1.90/hr until someone noticed.

Current state: KEDA is now protected by 3 safety layers. GPU nodes are always torn down when idle — no scenario leaves KEDA paused indefinitely.

LayerMechanismCatches
1. KEDA idle timerScaledObject monitors Prometheus. 15 min no requests → scale to 0 → Karpenter terminates GPU nodeNormal idle
2. Trap handlerScript interrupt (Ctrl+C / kill / terminal close) → cleanup_on_interrupt() removes paused annotation → KEDA resumesUser interrupts script
3. EventBridge safetyGPU controller Lambda checks paused-at timestamp. If paused > 15 min → auto-unpauses KEDAScript crash where trap didn't fire

cleanup() {
  echo ""
  log "Interrupted! Unpausing KEDA..."
  kubectl annotate scaledobject \
    ollama-autoscaler -n ollama \
    autoscaling.keda.sh/paused- \
    gpu-controller/paused-at- \
    --overwrite 2>/dev/null || true

# terraform/modules/api-gateway/lambda/auto_scale_trigger.py
import boto3, json, base64, urllib3

def handler(event, context):
    # Use EKS bearer token (short-lived STS presigned URL)
    eks = boto3.client('eks')
    cluster = eks.describe_cluster(name='eks-ollama-dev')
    endpoint = cluster['cluster']['endpoint']

    # Check current replicas
    replicas = get_ollama_replicas(endpoint)

    if replicas == 0:
        # Trigger scale-up
        patch_ollama_replicas(endpoint, 1)
        pause_keda(endpoint)  # Prevent KEDA from scaling back to 0

        return {
            'statusCode': 503,
            'headers': {
                'Retry-After': '180',
                'Content-Type': 'application/json'
            },
            'body': json.dumps({
                'error': {'message': 'Model is loading. Please retry in ~3 minutes.', 'type': 'model_loading'}
            })
        }

    # Ollama is running — proxy to NLB (or return 200 passthrough)
    return {'statusCode': 200}

# - Scheduled daily, 7-day retention
# Recovery: velero restore create --from-backup daily-xxx

Installation

# Install Velero:
helm repo add vmware-tanzu https://charts.velero.io
helm install velero vmware-tanzu/velero \
  --namespace velero --create-namespace \
  --set configuration.backupStorageLocation.bucket=ollama-velero-backups \
  --set configuration.backupStorageLocation.config.region=ap-southeast-2 \
  --set configuration.provider=aws \
  --set initContainers[0].name=velero-plugin-for-aws \
  --set initContainers[0].image=velero/velero-plugin-for-aws:v1.9.0

# Schedule daily backup:
velero schedule create daily-backup --schedule="0 2 * * *" \
  --include-namespaces ollama,open-webui \
  --ttl 168h   # 7 days retention

Cost: ~$5/mo (S3 storage). Benefit: Full disaster recovery + environment cloning.

ARCH 8. GitOps Secret Management (ESO + AWS Secrets Manager)

Current: Terraform creates K8s secrets directly. No rotation, secrets in Terraform state.

# Install External Secrets Operator:
helm install external-secrets external-secrets/external-secrets \
  --namespace external-secrets --create-namespace

# k8s/open-webui/external-secret.yaml
apiVersion: external-secrets.io/v1beta1
kind: SecretStore
metadata:
  name: aws-sm
  namespace: open-webui
spec:
  provider:
    aws:
      service: SecretsManager
      region: ap-southeast-2
      auth:
        jwt:
          serviceAccountRef:
            name: open-webui-sa
---
apiVersion: external-secrets.io/v1beta1
kind: ExternalSecret
metadata:
  name: webui-oauth-cognito
  namespace: open-webui
spec:
  refreshInterval: 1h
  secretStoreRef: { name: aws-sm, kind: SecretStore }
  target: { name: webui-oauth-cognito }
  data:
    - secretKey: OAUTH_CLIENT_ID
      remoteRef: { key: ollama/cognito/oauth }
      property: client_id

Benefit: Automatic rotation. Secrets never in Terraform state. Full CloudTrail audit.

ARCH 9. Istio Waypoint Proxy for L7 Per-User Rate Limiting

Current: Istio ambient mesh provides L4 mTLS only. WAF rate limit is per-IP, not per-user.

# k8s/ollama/waypoint.yaml
apiVersion: gateway.networking.k8s.io/v1
kind: Gateway
metadata:
  name: ollama-waypoint
  namespace: ollama
  labels:
    istio.io/waypoint-for: service
spec:
  gatewayClassName: istio-waypoint
  listeners:
    - name: mesh
      port: 15008
      protocol: HBONE

# Then add AuthorizationPolicy for per-user rate limiting:
apiVersion: security.istio.io/v1
kind: AuthorizationPolicy
metadata:
  name: ollama-rate-limit
  namespace: ollama
spec:
  targetRef:
    kind: Gateway
    name: ollama-waypoint
  action: DENY
  rules:
    - when:
        - key: request.headers[x-user-id]
          notValues: ["*"]

When to implement: Production with multiple users. Prevents GPU monopolization.
