4. Custom Login Portal — auth_proxy Lambda

The login portal is a single-page app (login.html on S3) + a Lambda backend (auth_proxy.py) that handles all authentication flows without exposing the Cognito hosted UI.

Endpoints

EndpointMethodInputWhat It Does
/portal/api/auth/login POST {email, password} Validates credentials, detects first-time challenges, drives OAuth flow
/portal/api/auth/mfa POST {totp_code, session} Verifies TOTP code, completes OAuth flow, returns session token
/portal/api/auth/change-password POST {new_password, session} Responds to NEW_PASSWORD_REQUIRED challenge
/portal/api/auth/setup-mfa POST {totp_code, session} Enrols TOTP device — AssociateSoftwareToken + VerifySoftwareToken
/portal/api/auth/forgot-password POST {email} Sends verification code via email (ForgotPassword API)
/portal/api/auth/confirm-reset POST {email, code, new_password} Resets password with verification code (ConfirmForgotPassword API)

Two-Phase Login Strategy

The login endpoint uses a two-phase approach to handle both first-time users and returning users:

1
Phase 1 — Cognito API Detection: Calls InitiateAuth with USER_PASSWORD_AUTH. If the response contains NEW_PASSWORD_REQUIRED or MFA_SETUP, the user is first-time — return the challenge to the frontend for interactive handling.
2
Phase 2 — OAuth Flow (server-side): If no first-time challenge is detected, the Lambda drives the full Cognito OAuth flow server-side: starts at Open WebUI's /oauth/oidc/login, follows redirects to Cognito hosted UI, extracts CSRF tokens, POSTs credentials, handles MFA form, captures the OAuth callback, and returns the Open WebUI session token.
Why scrape the hosted UI? Cognito's InitiateAuth API returns raw tokens (id_token, access_token) — but Open WebUI needs an OAuth authorization code exchange to create its own session. The only way to get that code is through the hosted UI OAuth flow. The Lambda automates this entirely server-side so the user never sees the hosted UI.

9. Socket.io Authentication

CloudFront VPC Origins Limitation: WebSocket protocol upgrade is not supported through CloudFront VPC Origins. Socket.io is configured for HTTP long-polling instead (ENABLE_WEBSOCKET_SUPPORT=false). Without this, socket.io silently fails and chat falls back to SSE streaming, triggering a known frontend JSON parse bug.

How Socket.io Auth Works

1
Frontend reads localStorage.token (originally from the token cookie)
2
Socket.io client sends polling request to /ws/socket.io/?EIO=4&transport=polling with auth: {token: localStorage.token}
3
CloudFront Function allows /ws/* path (excluded from auth redirect)
4
Open WebUI socket.io middleware validates the token from the handshake
5
If valid → session established. Chat streaming uses socket.io events over HTTP polling

Why Not WebSocket?

TransportCloudFront VPC OriginsStatus
WebSocket (wss://)Protocol upgrade fails through VPC OriginBroken
HTTP Long-PollingStandard HTTP requests, fully supportedWorking

11. Security Properties

Users Never See Cognito Hosted UI

The custom login portal drives the entire OAuth flow server-side. The Cognito domain is only used for server-side token exchange.

No Local Passwords

ENABLE_PASSWORD_AUTH=false disables all local password management. Passwords are managed exclusively via Cognito through the custom portal.

Mandatory TOTP MFA

Every user must enrol an authenticator app on first login. MFA cannot be skipped or disabled. TOTP codes are single-use per 30-second window.

Admin-Gated Access

Self-service signup creates the account, but users cannot access the platform until an admin adds them to a Cognito group.

Cognito = Source of Truth

Roles sync from Cognito groups on every login. Local role changes in Open WebUI are overwritten. Remove a user from the Cognito group → immediate access revocation.

No User Enumeration

Login and forgot-password endpoints never reveal whether a user exists. All error messages are generic: "Invalid email or password".

Internal NLB Only

The NLB is internal scheme in private subnets. No public IP. Only reachable via CloudFront VPC Origins (private AWS backbone).

Edge Protection

WAF rate limiting (2000/5min), IP allowlist, geo-blocking (AU/US), SQL/XSS rules, and DDoS protection (Shield Standard) at the CloudFront edge.
